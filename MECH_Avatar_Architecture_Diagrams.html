DIAGRAM 03

Lambda 06 — 15-Stage RAG Pipeline

Per question · ~2–8 seconds end-to-end

01
Cache Check
SHA256(query + filters + top_k + CODE_VERSION) lookup in DynamoDB. TTL=24h. Min confidence=0.6 to cache. ~40% hit rate for repeat queries. Returns in <100ms on hit.
DynamoDB
⚡ STAGES 2a · 2b · 2c — Executed in parallel via ThreadPoolExecutor (max 3 workers, 5s timeout each)
Stage 2a
Intent Classification
Classifies into: definition · procedure · troubleshooting · comparison · configuration · security · open_ended. Adjusts top_k + content_type_boost per intent.
Haiku
Stage 2b
Query Embedding
Generates 1024-dimensional dense vector for the query using Titan Embeddings V2. Same model used for documents — ensures same embedding space for KNN.
Titan V2
Stage 2c
Requirements Extraction
Extracts: required_topics · key_terms · expected_doc_types · importance_indicators · multi_doc_required flag. Used to inject hints into context.
Haiku
03
Entity Extraction
Regex-based extraction of mainframe entities from query: TSS IDs (ABC1234), table names (MY*, BDD*, MDD*), error codes, ABEND codes, program names, JCL job names, VSAM datasets.
Regex · ~5ms
04
Query Expansion / HyDE
For complex queries: HyDE generates a hypothetical MECH document excerpt to embed instead of bare query. Multi-part questions decomposed into 2–4 sub-queries for independent retrieval and RRF fusion.
Haiku
05
Hybrid Search (KNN + BM25)
function_score query: KNN semantic (0.7) + BM25 keyword (0.3) + entity terms boost (2×) + content_type_boost (1.5×) + source_priority boost (1.0–2.0×). Multi-query results fused with RRF k=60.
OpenSearch
06
Document Diversity
Best chunk per unique document collected first. Remaining TOP_K slots filled by score from remaining pool. Ensures cross-document synthesis — prevents all chunks from single high-scoring file dominating context.
In-memory · ~2ms
7a
Entity-Aware Reranking
Boosts chunks containing extracted query entities. For each match: score × (1 + 0.1 × entity_count × 1.5). Fast deterministic boost before expensive cross-encoder.
In-memory · ~5ms
7b
Cross-Encoder Reranking
Haiku scores each chunk 0.0–1.0 for direct query relevance. Final score = 0.4 × retrieval_score + 0.6 × cross_encoder_score. Top 12 chunks scored per call. Remainder get neutral 0.5.
Haiku · ~800ms
08
Context Compression
Haiku removes sentences from chunks that are irrelevant to the query. Max compressed tokens = 4,000. Reduces context noise before passing to Sonnet, improving answer focus.
Haiku
09
Context Reordering
Lost-in-middle mitigation: most relevant chunks placed at start and end of context window. Lower relevance chunks placed in middle. LLMs attend more strongly to beginning and end.
In-memory · ~1ms
10
Context Building
Assembles structured context with document labels, page numbers, section titles. Injects importance indicators from Stage 2c as [CRITICAL IDENTIFIERS TO VERIFY] header above context.
String builder
11
Answer Generation
Claude Sonnet 3.5 with intent-aware system prompt. Strict grounding rules: USE ONLY provided documents, NEVER fabricate, QUOTE relevant text, CITE all sources. Max output 5,000 tokens.
Sonnet 3.5 · ~3–6s
12
Grounding Verification
Checks answer claims against retrieved context. Statuses: fully_grounded · partially_grounded · weakly_grounded · ungrounded. Weakly/ungrounded answers get warning appended to response.
Regex + string match
13
Confidence Calibration
Multi-factor: avg retrieval score (60%) + grounding score (40%). Optionally overridden by calibration heuristics. Low confidence triggers answer reformatting with explicit uncertainty markers.
Heuristic
14
Final Confidence Score
Blends: avg_retrieval_score × 0.6 + source_coverage × 0.2 + intent_confidence × 0.2. Then: search_conf × 0.6 + groundedness × 0.4 = final confidence (0.0–1.0).
Formula
15
Cache Write + Async Memory
If confidence ≥ 0.6: cache answer in DynamoDB (24h TTL). Async invoke Lambda 09 to store Q&A pair in session memory for follow-up questions.
DynamoDB · Lambda 09
